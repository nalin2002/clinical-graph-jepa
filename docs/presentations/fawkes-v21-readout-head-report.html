Clinical Graph-JEPA · Engineering Report No. 5

v21: the readout head was the wrong one

Swapping DistMult for the MLP edge head — a switch that has existed in the paper implementation since v16 and had never been flipped — raises leave-one-out MRR from 0.417 to 0.471. It wins at every seed, on every metric that is correctly constructed, and on all four of the paper's inferred relations. The one metric that appeared to regress turned out to be measuring the wrong thing. §8–§11 work backwards through v20, v19, v18 and v16/v17 so the lineage stays traceable from one document.

The one apparent regression was a broken metric

Batch-mask auc_nonobvious showed the MLP losing by 0.0713 at 10/10 seeds — the only negative result anywhere in this experiment. It is an artefact: _classification_metrics filters the positives to non-patient-anchored edges but compares them against the unfiltered negative pool, which is 68% patient-anchored. Drawing negatives from the same population flips the sign to +0.041. §4 has the reproduction. This is a pre-existing bug that also inflates the published auc_nonobvious of 0.800.

§2v21 — what changed and why

v21 · readout head
No source changes. One environment variable, one arm, ten jobs. The baseline arm is v20, reused rather than re-run.

The head was already there

zero code added build_scorer returns DistMult when DECODER=distmult and an MLP Scorer otherwise, and it has done so since the original trainer — its docstring still cites trainer.py:630. The config pin confirms it: decoder maps to the real trainer global DECODER, not to null as genuinely new fields like mask_strategy and data_split_seed do.

This is the same architecture clinical_jepa scores edges with (EdgePlausibilityHead: a relation embedding plus an MLP over [src ; tgt ; rel]), differing only in ReLU against GELU. Porting the GELU variant was rejected: an activation change is far below the ±0.019 noise floor v20 measured, and resolving it would cost another ten jobs to conclude nothing.

The path had never been executed or tested

No prior version ran DECODER=mlp, and grep "Scorer\|decoder" tests/test_fawkes.py returns nothing — the config parsing is pinned (the pin's non-default environment sets DECODER=MLP) but no test ever instantiated the model. A local smoke run at 2+2 epochs was the first end-to-end execution of this code path in the tree; it completed, trained and evaluated cleanly before the fleet was submitted.

decoder is not in checkpoint_dict(), so a v21 checkpoint is indistinguishable from a v20 one by its config block — the same blind spot that made v19's arms C and Cp serialise identically. The output repository name is the provenance record, and re-evaluating a v21 checkpoint requires DECODER=mlp or the strict state_dict load fails on the mlp.0.* keys DistMult does not carry.

Why only ten jobs

The v20 runs are the DistMult arm: same split, same seeds, same configuration, DECODER at its default. So v21 submitted one arm and compared against stored checkpoints. Better still, the scorer is only built in phase 2, after pretrain_jepa returns, and FREEZE_ENCODER=1 means the encoder never moves afterwards — both arms run the identical, identically seeded phase 1. This isolates the readout head against the same encoder. The pairing is tight but not exact: the hardware nondeterminism of §9 still sits inside each pair.

§4The non-obvious AUC regression is a measurement artefact

One result in this experiment pointed the other way, and it pointed hard: the MLP lost auc_nonobvious by 0.0713 at every seed. A single consistent negative amid seven consistent positives is exactly the kind of thing that deserves investigating rather than reporting, because it either qualifies the conclusion or reveals a defect. It was a defect.

What the metric does

"Non-obvious" means the held edge's source is not the PATIENT node — entity-to-entity relations rather than the trivially predictable patient backbone. The intent is a harder subset. The implementation filters the positives to that subset and then scores them against every negative, including the ones drawn for patient-anchored positives:

negatives is neg_scores[:, 0] — one negative per positive, same length, same order — so nonpat_mask indexes it correctly. The as-shipped version compares 2,509 non-patient positives against all 7,766 negatives, of which 68% belong to patient-anchored edges. Those are easy to beat, so the metric is inflated for both arms, and it is inflated unequally.

The bug predates v21 — it is in the evaluation path inherited from the original trainer, so the released checkpoint's auc_nonobvious of 0.800028 is inflated by the same mechanism. Only that one metric is affected: auc and ap compare all positives against all negatives, which is matched by construction, and MRR/Hits/LOO never touch this code. If Table 1 or the text quotes a non-obvious AUC, it needs recomputing before the revision goes out.

§5Where the gain lands

An aggregate MRR can improve because a model got better at the easy majority. That would be a much weaker result for this paper, whose subject is the four LLM-inferred relations. It did not happen: leave-one-out evaluates almost exclusively those relations, and the MLP wins every one of them at all ten seeds.

This retires the released checkpoint as the paper artifact

Reporting the MLP numbers means the released checkpoint no longer produces Table 1, and every gate pinned to it — test_loo_reproduces_published_test_split, baseline/paper_loo_testsplit.json, the checkpoint_dict equality test — now pins a historical artifact rather than the current claim. Those tests should stay (they are the regression net for the data path), but a v21 checkpoint has to be released alongside, and the paper must say which one it describes.

§7What this does not establish

  • Still one split. All twenty runs hold out the same 400 admissions, and the review's question about the patient sample remains open. v20 §6 has the four-job fix; it applies to both arms now, which doubles it to eight.
  • The MLP is not "the clinical_jepa head". It is the same architecture with ReLU where clinical_jepa uses GELU. Nothing here tests that difference, and nothing here validates the rest of panel C — the schema guard, candidate generation and KEEP/REVIEW/PRUNE remain unimplemented in fawkes.
  • Parameters are not controlled. The MLP head adds ~49k parameters over DistMult's relation embedding. This experiment shows the head is better; it does not separate "better architecture" from "more capacity". A width-matched DistMult, or an MLP shrunk to parameter parity, would.
  • Cascade and EIR are still empty. Both arms ran RUN_CASCADE=0 and RUN_EIR=0.
  • The corrected non-obvious AUC is measured on three seeds, not ten, and on CPU. It establishes the sign flip and the mechanism; the fleet-scale number needs the metric fixed and both arms re-scored.
  • No test covers the MLP path. The arm ran clean across ten jobs, but the regression gate that would catch a future break still does not exist.

The artifact rule this series keeps re-learning

Config.checkpoint_dict writes a hand-picked subset of fields. It omits jepa_epochs, readout_epochs and freeze_encoder — which is why v19's arms C and Cp serialise identically — and it omits data_split_seed and decoder too. A v21 checkpoint therefore cannot be distinguished from a v20 one by its config block, and loading one without DECODER=mlp fails a strict state_dict load. From v19 on, the job name and output repository are the provenance record.

§9v20 — the seed variance study

v20 · split/seed separation
One config field, one line in the splitter, one regression test. No change to any published number.

A reviewer asked for mean ± std across seeds and splits, on the grounds that the paper reports one particular random sample of patients. Before v20, _split_items keyed its permutation on cfg.seed — the same value seeding the model — so changing SEED resampled the patients and reinitialised the model at once. data_split_seed separated them, defaulting to 42 so the published split is unchanged.

Ten retrains of the paper configuration gave LOO MRR 0.4174 ± 0.0190, with all four published metrics inside the 95% CI and AUC agreeing to 0.0002. The published number was not a lucky draw. But the spread is large — Hits@1 varies by 9.4% of its mean — and it established the 0.0238 minimum detectable difference that makes v21 readable. v20 also found that no retrain in the lineage had ever reproduced the published number as a point: every apparent reproduction re-evaluates the released checkpoint.

v20's open item, still open

Every run in v20 and v21 uses DATA_SPLIT_SEED=42. The split axis is unmeasured, so the reviewer's actual question — is it a lucky sample of patients — remains unanswered. v20 §6 also recorded that the split is by admission, not by patient: 139 subjects appear in both train and test, and 36.8% of test admissions belong to a patient the model trained on.

§10v19 — the JEPA pretraining ablation

v19 · ablation harness
No new configuration. One model-selection bug fixed, six arms over the existing env surface.

Asked how much of the result comes from JEPA pretraining rather than from having any graph encoder, six arms across three seeds answered: a frozen randomly initialised encoder scores the same as the JEPA-pretrained one (−0.008, sign flipping across seeds), while the same architecture trained end-to-end without phase 1 beats both by +0.311 MRR. An encoder with message passing removed entirely still beat the paper model by +0.23.

v19's proposed mechanism: under FREEZE_ENCODER=1 the 8,192 × 128 entity embedding table is only ever shaped by the pretext task, and in arm B never trained at all. §11v18, v17 and v16 — the earlier lineage

v18 — BFS-balanced patch masking

v16's pretext task masks nodes i.i.d. Bernoulli at 0.4, which lets the model solve masking by local interpolation from surviving neighbours. v18 added MASK_STRATEGY=patch: partition each graph into 8 BFS-balanced patches and mask whole patches, so a masked node's neighbours are usually masked too. Results were no-note +0.0237 and with-note −0.0107, one seed per cell. Both sit inside the ±0.019 v20 later measured, so neither is resolvable — and the with-note comparison set a freshly trained patch model against the released checkpoint, making it unpaired as well as underpowered.

v17 — the refactor that had to move nothing

paper_v16/trainer.py read ~30 os.environ values at import and computed a tensor shape from them, so environment variables had to be set before import, two configurations could not coexist in one process, and the trainer was untestable. v17 split it into fawkes/{config,data,model,steps,train,evaluate}.py with every global becoming a Config field. The success criterion was equality: LOO to 1e-6, identical state_dict keys, and an AST gate proving no module-scope environment reads remain. All three still pass under v21. It is that verbatim-preservation requirement that carried DECODER forward, which is why v21 needed no code.

v16 — the experiment that produced the published number

v15 attached the Clinical-ModernBERT note embedding to a single per-admission NOTE node. v16 retired it and localised the same 768-dimensional vector onto the entity nodes the note actually grounds — by default the endpoints of any edge carrying prov_in_note, which is 28.6% of nodes on the shipped dataset. Ungrounded entities receive a zero vector.
