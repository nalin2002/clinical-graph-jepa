Clinical Graph-JEPA · Engineering Report No. 2

v18: BFS-balanced patch masking — what changed, and what it did to the numbers

v18 replaces the JEPA pretext task's i.i.d. node mask with whole-patch masking borrowed from clinical_jepa. This report covers the change and its measured effect against v17, then works backwards through v17's refactor and the v16 experiment that started it.

repo clinical-graph-jepa runs 4 (2 versions × note/no-note) eval LOO, 8,283 edges date 2026-08-04

§1The verdict, first

Patch masking is a clear win for the no-note variant and a mild regression for the with-note variant. On leave-one-out edge recovery — the paper's honest measure — the no-note model gains on every metric and every relation, while the with-note model loses ground on the three relations that carry 98% of the evaluated edges.

Because the note's whole purpose is to supply semantic signal the graph structure lacks, the two results together tell one story: patch masking recovers part of what the note was providing. The note's advantage over the structure-only model narrows from +0.144 to +0.110 LOO MRR. Section 4 argues why that is the mechanism you would predict, and section 5 is honest about what a single run per cell can and cannot establish.

§2v18 — what changed and why

v18 · patch masking
One new module, one branch in jepa_step, two config fields. The default is still the v17 behaviour, so v18 is opt-in.

The problem with the v16/v17 mask

JEPA phase 1 masks a fraction of nodes and asks the model to predict their embeddings from what remains. Through v17 that mask was i.i.d. Bernoulli: each node independently masked with probability node_mask=0.4, retried until every graph kept at least one target and one context node.

The weakness is structural. Masking nodes independently means a masked node's immediate neighbours are almost always still visible — with 40% masking, a node of degree 5 keeps ~3 visible neighbours on average. The prediction task can therefore be solved by local interpolation: read the surviving neighbours, average, done. A pretext task solvable one hop out does not force the encoder to learn anything longer-range, which is exactly the capability edge recovery needs.

What v18 does instead

new Each graph is partitioned into jepa_patches balanced, connected-ish patches by multi-source BFS, and whole patches are masked until the node_mask fraction is reached. Targets become coherent regions rather than scattered nodes, so a masked node's neighbours are usually masked too and the local shortcut disappears.

The partition is adapted from clinical_jepa/graph/patches.py, the patch construction behind the patch-based model. Seeds are chosen farthest-point style — highest degree first, then greedily maximising distance from existing seeds — then BFS grows all patches in parallel with a size cap, and any node left over by a disconnected component is reseeded into the currently smallest patch.

Keeping the last-drawn patch as context means the ≥1-target / ≥1-context guarantee that valid_mask achieved by retrying now holds by construction — with jepa_patches ≥ 2, which the config validates.

Why it was duplicated rather than imported

tests/test_import_boundaries.py forbids fawkes and clinical_jepa from importing each other — the two lineages are deliberately independent, and that test is what keeps them so. The partition is therefore copied near-verbatim into src/fawkes/patches.py with its provenance recorded in the module docstring. Only the partition came across: the coarsened patch graph, positional features and patch pooling stay in clinical_jepa, because in fawkes patches only decide which nodes get masked — the encoder still operates on nodes.

Configuration

Four new tests cover the patch path: config validation, partition coverage and balance, per-graph mask coherence, and an end-to-end jepa_step on real dataset graphs.

§3v18 vs v17 — results

Four runs, all on the same 4,000-graph dataset with the same seed, the same 3200/400/400 split, and every hyperparameter except the mask identical. The v17 numbers come from the two released checkpoints; the v18 numbers from training runs on an A100.

The four runs were scored on bit-identical queries

Every run reports quiz_sig=304815655090 and n_mrr=3000 for batch-mask, and n=8283 LOO edges. That signature is a hash of the held-edge and negative-sample draw, so its equality across all four runs means the four models were asked exactly the same questions. Nothing in the evaluation moved; only training did.

Leave-one-out edge recovery

LOO masks exactly one edge and keeps the entire rest of the graph as context. It has no randomness, so it is exactly reproducible, and it is what the paper reports.

Cascade headroom — a structural fix in the no-note model

The cascade evaluation brackets each inferred relation between a floor (backbone edges only) and a ceiling (LOO, everything else present). The gap between them is the headroom that context is worth. In v17's no-note model, that headroom was negative for two of the four inferred relations — giving the encoder the full graph made it worse than giving it the backbone alone. In v18 all four are positive.

This is the most mechanistically interesting result in the report, because it is not just "the number went up." A negative headroom means surrounding context was actively confusing the v17 no-note encoder. After patch-mask pretraining, context helps on every relation. That is precisely the capability the harder pretext task was meant to install.

Training cost

On an A100, the with-note v18 run took about 15 minutes end to end (JEPA epochs ~7.5 s, readout epochs ~9.3 s) and the no-note run about 12.5 minutes. Target-embedding standard deviation held near 0.50 throughout both runs, so the BYOL objective did not collapse under the harder mask. No training logs survive for the v17 runs, so this report makes no wall-clock comparison between versions — the BFS partition is per-graph Python and certainly costs something, but the size of that cost is not measured here.

§4Reading the result

The two arms moving in opposite directions is not noise-shaped; it has a mechanism, and the mechanism predicts the sign of each.

The Bernoulli mask leaves a masked node surrounded by visible neighbours, so phase 1 can be solved by local interpolation and the encoder is never pushed to represent anything longer-range. The with-note model does not need it to be. Its nodes already carry a 768-dimensional Clinical-ModernBERT vector describing the admission, so the semantic content that would otherwise have to be inferred from distant structure is handed to it directly. Make the pretext task harder and you mostly add noise to a model whose signal was arriving by another channel — which is what the −0.065 on COMPLICATED_BY looks like.

The no-note model has nothing but structure. Six demographic features per node and the graph. For it, an easy pretext task is a wasted one: it never learns the long-range structural regularities that edge recovery depends on, and the negative cascade headroom in v17 is the fingerprint of that failure — it could not use context it had never been trained to read. Patch masking removes whole neighbourhoods and forces exactly that skill, and every no-note metric responds.

Hence the narrowing note lift: +0.144 → +0.110 LOO MRR. Some of what the note was contributing was compensation for an under-trained encoder, and a harder pretext task recovers part of it for free — no text, no 768 extra input dimensions, no Clinical-ModernBERT dependency at inference. For a deployment that cannot rely on note availability, that is the useful finding.

§5What this does not establish

One run per cell — no variance estimate

Each of the four numbers is a single training run at seed=42. Nothing here measures run-to-run variance, so any difference of roughly ±0.01 MRR should be treated as possibly noise. That specifically covers the with-note MRR regression (−0.011) and its Hits@3 (−0.003). The no-note gains (+0.024 MRR, +0.035 Hits@3), the COMPLICATED_BY with-note regression (−0.065), and the cascade headroom sign flips are larger and more likely real — but "more likely" is the honest phrase. Three to five seeds per cell would settle it.

  • Small-n relations are not evidence. CONFIRMS (n=125) and TARGETS_ORGANISM (n=25) produce the biggest-looking deltas in the report and deserve the least weight. The trustworthy relations are MANAGED_FOR, INDICATES and COMPLICATED_BY.
  • Hardware differs between versions. The v17 checkpoints come from earlier runs on unknown hardware; the v18 runs are on an A100. Bit-level determinism is not guaranteed across devices, though the effect is far smaller than the deltas discussed here.
  • jepa_patches=8 was not tuned. It was inherited from clinical_jepa's num_patches default. Patch count controls how much of each graph vanishes at once and is the obvious first sweep — as is node_mask, which was left at 0.4 and interacts with patch count.
  • Only the pretext task changed. Phase 2 readout training and all four evaluators are untouched, which is what makes the comparison clean but also means this says nothing about whether the readout should change too.

Recommendation: keep random as the default, which it is; use patch for the no-note variant; and run a seed sweep before treating the with-note regression as real.

§6v17 — the refactor, and how it compares to v16

v17 · engineering only
Same model, same numbers to within 1e-6, same environment interface — split into modules, made importable and testable.

no numerics changed v17 is the release that made v18 possible, and it deliberately produced no metric movement. It compares to v16 by equality, not by improvement: loading the released checkpoint and running LOO reproduces the recorded baseline to within 1e-6 on every metric.

What v16 was, and the four problems v17 fixed

v16 lived in one file — paper_v16/trainer.py, 719 lines — plus a separate checkpoint-only evaluate.py. It produced the released checkpoint and the published metrics, and it had four structural problems:

  • It configured itself from the environment at import time. Roughly thirty os.environ reads ran when Python imported the module, and NUMERIC_DIM — a tensor shape — was computed at import. Environment variables had to be set before the import, two configurations could not coexist in one process, and the trainer was effectively untestable.
  • Everything shared one namespace. Data loading, the model, both training phases, four evaluators and reporting were interleaved; the standalone evaluate.py reached into trainer.USE_NOTE to validate checkpoints.
  • --help trained the model. main() took no arguments and ran unconditionally, so fawkes-train --help completed a full training run and — with PUSH=1, the default — uploaded the result.
  • The tensor code was hard to read (b, nt, ei, tot_llm), and the checkpoint filename was a hardcoded date stamp.

The split

trainer.py was cut at its own existing comment banners — lines 256 ("shared encoder"), 327 ("downstream readout"), 423 ("EIR scoring") — rather than at invented boundaries, and paper_v16/evaluate.py was folded in as the checkpoint CLI.

modulecontents
config.pyConfig — every knob; from_env(), from_checkpoint(), checkpoint_dict(), checkpoint_name
data.pyvocabularies, score_vec, load_full_dataset, to_data
model.pyEncoder, JEPA, DistMult, Scorer
steps.pyper-batch tensor work: jepa_step, readout_step, negative sampling — where v18's branch lives
train.pythe run: set_seed, data prep/split, both phases, reporting, main
evaluate.pythe four evaluators, shared ranking helpers, checkpoint CLI

Env globals became a dataclass

That refactor is what made v18 a two-field change rather than another round of import-time globals — and what let this report evaluate a note and a no-note configuration in the same process.

v17 vs v16 — equality, gated three ways
  • Loading the released checkpoint and running loo_evaluate reproduces baseline/paper_loo.json to within 1e-6 on every metric.
  • Encoder().state_dict() and DistMult().state_dict() key sets equal baseline/paper_keys.json — these are attribute paths, so a renamed submodule shows up here and nowhere else.
  • Importing fawkes with no environment set raises no error and reads no os.environ at module scope (AST-verified).

The plan carried an explicit stop rule: if either numeric gate failed, the refactor would be abandoned and trainer.py kept verbatim — "an unverifiable refactor of the paper artifact is not worth the readability gain." The gates passed. Three deliberate behaviour changes shipped, and only three: variant-derived checkpoint names (fawkes_entity_note.pt / fawkes_no_note.pt), CUBLAS_WORKSPACE_CONFIG moved from import into set_seed, and the argument-parse guard that stops --help from training and publishing.

§7v16 — the experiment underneath all of this

v16 · the paper artifact
The entity-grounded-note Graph-JEPA, run 260615. The released checkpoint and every published number come from here.

One hazard to state, because it inverts what the repository name suggests: fawkes is the implementation behind the paper (paper/clinical_jepa.pdf), and clinical_jepa is not — it is the separate modular revision pipeline that v18 borrowed the patch algorithm from. This is documented in docs/LINEAGE.md, stated in both package docstrings, and enforced by tests/test_import_boundaries.py. The "16" is an experiment number from a separate line of work, not the successor to the v5/v6 architecture names in clinical_jepa.

The experiment

A JEPA world model over per-admission clinical knowledge graphs, trained in two phases on 4,000 admission graphs (3,018 subjects, 85,290 LLM edges):

  • Phase 1 — the world model. Masked-node latent prediction, BYOL-style, with an EMA target encoder on one shared encoder. This is the phase v18 changes.
  • Phase 2 — the readout. Frozen-encoder edge recovery with InfoNCE over same-type negatives, the four inferred relations upweighted (target_weight=3.0), and the scorer rolled back to its best validation-AUC epoch.

v16's own contribution — the thing the "entity-note" name refers to — was localising the Clinical-ModernBERT note vector onto the entity nodes the note actually grounds (28.6% of nodes under ground_by=prov), replacing v15's single per-admission NOTE node. NOTE and HAS_NOTE remain in the vocabulary, unused, as evidence of that retirement.

The four evaluators

They answer different questions and are not interchangeable — worth restating, because section 3 quotes three of them:

  • loo_evaluate — mask exactly one edge, keep the whole rest of the graph. No randomness, exactly reproducible. The honest per-relation measure and what the paper reports.
  • evaluate — batch-mask: 30% of edges held out together. Harder and noisier.
  • cascade_evaluate — recover the inferred relations in order, adding each one's gold edges to context before the next. Produces the floor/ceiling bracket used above.
  • eir_uplift_eval — refiner precision/recall against v8-gold triples. Off by default; full-gold F1 is hub-dominated.

If you do one thing next

Run three to five seeds per cell. The no-note improvement and the cascade headroom sign flips are the findings worth defending, and a seed sweep is what turns them from suggestive into solid — while settling whether the with-note regression is real or a single unlucky run.
